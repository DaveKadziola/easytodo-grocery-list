# EasyToDo v2.2 Implementation Plan (phone keyboard + PL/EN/DE)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A tap outside an open menu only closes it. The keyboard on a phone no longer hides the field being edited. The whole UI, server messages and mails are available in Polish, English and German, chosen per account.

**Architecture:** One shared touch guard in `app.js` handles outside taps, and `interactive-widget=resizes-content` plus a focus scroll handles the keyboard. Translations use gettext: Babel reads the `.po` catalogs at start-up (in memory, no compiled `.mo` in git or in the image). A context variable holds the request's locale. A pure ASGI `LocaleMiddleware` sets it from the cookie or `Accept-Language`, and `require_user` overrides it with `users.language`. Jinja gets the `i18n` extension with new-style gettext. JavaScript gets a small `{msgid: translation}` dictionary embedded in `base.html`. Dates render as `<time>` in UTC on the server, and `app.js` rewrites them to the phone's local time with `Intl`.

**Tech Stack:** FastAPI, SQLAlchemy async, Alembic, Jinja2 + `jinja2.ext.i18n`, Babel (new dependency), HTMX, Alpine (CSP build), Playwright e2e.

**Spec:** `docs/superpowers/specs/2026-10-24-v2.2-spec.md` (copy: `/mnt/project-files/plans/v2.2/2026-10-24-v2.2-spec.md`).

## Global Constraints

- Languages: exactly `pl`, `en`, `de`. Default and fallback is `en`. msgids are the current English texts.
- Locale precedence for a request: `users.language` (signed in, not NULL) > cookie `lang` > `Accept-Language` (first supported primary tag by q) > `en`.
- Cookie `lang`: path `/`, max-age 31536000, SameSite=Lax, HttpOnly, Secure when `settings.cookie_secure`.
- `users.language`: `String(2)`, nullable, CHECK `language IN ('pl', 'en', 'de')`. Existing rows stay NULL. Accounts created by an admin are NULL. Registration (plain and by invite) stores the chosen value.
- A signed-in account with NULL language gets `/account/language` for every GET/HEAD page (after the password-change step, if one is owed). Any other method gets 403 "Choose your language first." There is no skip button.
- Mails: reset in the account's language, or the request's locale when the account has none. Invite in the recipient account's language when the account exists and has one, otherwise in the inviter's.
- Dates: `<time datetime="<ISO UTC>Z" data-local="datetime|date">`. `app.js` formats with `Intl.DateTimeFormat(document.documentElement.lang, …)`: PL/DE `{dateStyle:"short", timeStyle:"short"}`, EN `{dateStyle:"medium", timeStyle:"short"}` (date-only: `timeStyle` omitted), local time zone, no "UTC" suffix. The 2FA recovery `.txt` keeps UTC with "UTC".
- Not translated: the name "EasyToDo", user content, server logs, CLI output.
- Tone: Polish informal "ty", German informal "du". Glossary (use these terms everywhere):

| en | pl | de |
|---|---|---|
| board | tablica | Board |
| category | kategoria | Kategorie |
| item | pozycja | Eintrag |
| checklist | checklista | Checkliste |
| attachment | załącznik | Anhang |
| archive / archived | archiwum / zarchiwizowana | Archiv / archiviert |
| owner / editor / viewer | właściciel / edytor / przeglądający | Eigentümer / Bearbeiter / Betrachter |
| invite | zaproszenie | Einladung |
| sign in / sign out | zaloguj się / wyloguj się | anmelden / abmelden |
| two-factor code | kod 2FA | 2FA-Code |

- Same rules as v2.0/v2.1: every model change is an Alembic migration, `alembic check` stays clean, user text is autoescaped in every new view, new endpoints return 404 for ids that aren't the user's, and `tests/test_statement_budget.py` budgets don't grow.
- Performance: board, add and toggle p95 no slower than v2.1, using the v2.1 harness `/mnt/project-files/plans/v2.1/perf/bench.py`.
- Release: PR base `develop`, title `feat: languages PL/EN/DE and phone keyboard fixes`, merged with a merge commit. `pyproject` version `2.2.0`.

## Model per task (Dave's tiering)

Each task carries `Model:` (implementer) and `Review:` (independent per-task reviewer).
- **haiku**: mechanical work against a fixed recipe, and fix waves from a concrete review list.
- **sonnet**: typical tasks, translation-bearing tasks, and per-task reviews.
- **opus**: hard parts (touch guard, i18n core, release verification), reviews of opus tasks, and the final whole-branch review.

Escalation: if a reviewer rejects a task twice for the same issue, the next attempt runs one tier higher. The final review fix wave assigns each fix by the same rule.

## Review Focus

1. **Interleaved requests in different languages** (a PL user and a DE user at once, across `await`s) must never get each other's strings. Pinned by `test_locale_isolated_between_concurrent_requests` (Task 3).
2. **Names inside translated strings** (`<b>`, `"`, `%`, `{x}`, `100%`) must be escaped and must not crash formatting. Pinned by `test_translated_placeholder_escapes_and_keeps_percent` (Task 3) and `test_notification_with_hostile_name_renders_in_pl` (Task 10).
3. **NULL-language account on non-page traffic** (htmx POST, WebSocket, `/logout`, a password change still owed): no redirect loop, WebSocket still connects, password step comes first. Pinned in Task 4.
4. **Odd `Accept-Language`** (`*`, `pl-PL;q=0.8,de;q=0.9`, `xx`, empty, `de;q=0`, 4 KB of junk) negotiates without error. Pinned by the negotiation table in Task 3.
5. **Long German strings on a 375 px phone** (header, bottom bar, ⋮ menus, dialogs) must not overflow horizontally. Pinned by `test_de_phone_has_no_horizontal_overflow` (Task 13).
